# WebDesk 演示素材拍摄指南

> 面向 README、GitHub 仓库页、小红书、B 站 / YouTube。  
> 操作以**当前产品为准**：文件夹是**单击**打开（不是双击）；设置窗口**只有红点关闭**；Dock **关不掉**。  
> 完整 60–90 秒分镜可参考你桌面上的《WebDesk演示视频拍摄指南》；本文是「拍什么、给谁看、文件放哪」。

---

## 1. 先定结论（少拍、分平台）

不要指望一条 90 秒视频打天下。推广时三层素材就够：

| 优先级 | 形态 | 用途 | 建议规格 |
|--------|------|------|----------|
| **P0 必拍** | 1 张横图封面 | GitHub README 顶图、仓库 social preview、推特/博客 | 1920×1080 PNG/WebP，桌面全貌，无痕窗口、无 Token |
| **P0 必拍** | 1 条 8–15 秒 MP4 + 封面图 | README 首屏，3 秒看懂「能拖」 | 宽 800–960px，**MP4 现已控制在 2–4MB**（27MB 的 GIF 已退役，见 §3） |
| **P1 很值** | 1 条 60–90 秒无口播视频 | B 站 / YouTube，README 只放链接 | 1080p 30fps MP4，**不要提交进 git** |
| **P1 小红书** | 3–9 张竖图 + 可选 15–30 秒竖屏视频 | 封面靠「像 Mac 桌面」截图，不是靠长演示 | 3:4 或 9:16；中文大字叠加 |

口播可以不做。桌面指南里的「纯操作 + 英文字幕」对 GitHub / YouTube 仍然最合适；小红书用中文大标题即可。

## 2. 静态图：到底截哪几张

录视频之前先截这几张（无痕、缩放置 100%、1920×1080）。整理桌面：**8–12 个书签 + 2–3 个文件夹**，不要空、也不要上百个图标。

**给 GitHub / 英文社交（横图）**

1. **英雄图（必须）**：暗色壁纸 + Dock 悬停放大 + 时钟/待办都在，鼠标不要挡住图标。这是「这是什么」的唯一一张。
2. **文件夹开窗**：一个文件夹窗口叠在桌面上，能看出嵌套，不要把窗口拖出屏幕。
3. **设置（可选）**：亮/暗对比可用左右拼图；**不要出现 Token 明文**。

**给小红书（竖图，每张一句中文）**

建议 6 张轮播，顺序：

1. 封面：桌面全貌 + 标题「浏览器里的 Mac 桌面书签」
2. 拖一个图标（可加箭头标注）
3. 打开文件夹窗口
4. 搜索框出结果
5. 设置里切暗色 / 换壁纸（无 Token）
6. 结尾：Fork + Pages 地址 / GitHub 仓库二维码或短链

一张图只讲一件事。小红书封面不要用全英文长句。

**不必单独为「emoji 图标」拍一条视频**——在英雄图或短 MP4 里放 **1–2 个名称就是 emoji 的书签**（如 🐙、📝）即可被看见。

## 3. README 首屏：内嵌 MP4 播放器（GIF 已退役）

**2026-11-10 起不再用 GIF。** 旧的 `webdesk-demo.gif` 有 27MB，README 首屏要拉半分钟，
仓库 `.git` 也被它撑大；同一条录屏转成 H.264 MP4 只有 2.4MB，小了一个数量级。

11 秒左右的镜头就够：

1. 鼠标划过 Dock（放大）
2. **单击**打开文件夹
3. 把一个图标拖进文件夹（慢、停半秒）

到此为止。导入 HTML、GitHub 同步、等 5 秒推送，都留给长视频。

**文件与引用方式（2026-11-10 定稿）**

README 首屏现在是**内嵌播放器**，不是封面图链接。做法是把视频作为附件传到
GitHub（任何 issue / PR 里拖入即可得到 `user-attachments` 链接），然后把**链接单独一行**写进 README：

```
https://github.com/user-attachments/assets/<id>
```

GitHub 的 README 渲染器识别这种链接，自动展开成 `<details open>` + `<video controls muted>`，
宽度随 README 容器自适应。

**三个必须知道的坑**

| 坑 | 现象 |
|---|---|
| 直接写 `<video src="...">` 标签 | 标签会被保留但不会自动识别成附件播放器，只有浏览器原生行为，GitHub 不加样式 |
| 套一层 `<div align="center">` 或 `<p align="center">` | 外层收缩成 `width: fit-content`，视频的 `max-width:100%` 因此算出 **0px**，播放器完全看不见 |
| 用 `<p>` 包裸 URL | HTML 块内部的 Markdown 不再解析，链接不会变成播放器，只会显示成纯文本 |

所以：**裸链接、单独成段、外面什么也别包**。想要居中只能接受默认全宽（GitHub 不让改写容器）。

**视频文件不提交进仓库。** 视频托管在 GitHub 附件 CDN 上（issue #1 拖入生成的那条链接），
仓库里不留 mp4 / 封面图副本，README 也不引用本地文件。这样仓库体积不随视频增长。

导出参考（有 ffmpeg 时，压好后拖进任意 issue 拿附件链接）：

```bash
# 视频：压到 2–4MB 左右，960 宽
ffmpeg -i demo.mov -vf "scale=960:-2" -c:v libx264 -crf 26 -preset slow -an demo.mp4
# 可选：封面帧，取第 4 秒一帧（用于社交平台，不进仓库）
ffmpeg -ss 4 -i demo.mp4 -frames:v 1 -q:v 3 demo-poster.jpg
```

⚠️ 换掉大文件**不会缩小已有的 git 历史**，旧的 27MB GIF 仍留在历史里。要真正瘦身得重写历史
（`git filter-repo`），属于不可逆操作，需用户单独决定。

## 5. 平台怎么嵌

| 平台 | 嵌什么 | 不要嵌什么 |
|------|--------|------------|
| **GitHub README** | 英雄图 PNG + 短 MP4（封面图链接到视频）；下面一行 B 站/YouTube 链接 | 未打码 Token、自己的真实书签隐私 |
| **仓库 Social preview** | 与英雄图同一张（Settings → General → Social preview） | 过暗、字太小的截图 |
| **小红书** | 竖图轮播为主；视频用 15–30 秒竖屏切同一条横屏（裁中间） | 对着 GitHub Settings 录 Fine-grained Token 全过程 |
| **推特 / 即刻 / V2EX** | 英雄图 + 一句话 + 仓库链接；V2EX 可补 Fork 步骤 | 先丢 90 秒没字幕的片 |

小红书文案方向（不是功能清单）：「不装 App、Fork 就能用的桌面书签页」+ 一张像桌面的图。技术细节放 GitHub。

## 6. 拍摄注意（与桌面指南一致的部分）

- 无痕窗口；系统缩放 100%；关通知。
- 鼠标放大或高亮；拖拽匀速。
- 演示数据用「假书签」（文档站、工具站），不要录私人邮箱、公司内网。
- Token、Owner 输入框不要入镜明文。

拍完后把视频拖进任意 issue 拿到 `user-attachments` 链接，替换 README 里那一行即可——**不要提交进仓库**。
