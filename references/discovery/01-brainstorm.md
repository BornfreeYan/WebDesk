# WebDesk 头脑风暴

> ⚠️ **状态**：个人随手记录，未经讨论验证，所有内容为假设，可行性待评估。

## 一句话定位

运行于浏览器中的**个人桌面书签管理器**——本质是将网站书签以桌面图标的形式组织，提供类桌面点击交互。轻量 Web 应用为可选辅助。Your desktop on the web。

## 核心概念

- **本质是书签管理器**：把浏览器书签映射为桌面上的"软件"图标，按文件夹分类。桌面只是交互层隐喻，不是 Web OS。
- **去中心化部署**：面向开发者分发。用户 fork 仓库 + 填入 GitHub Token 即可生成自己的站点，无需服务器，开发者本身维护。
- **轻量替代本地**：用网页端替代一部分本地软件功能，保持实际桌面整洁、内存清爽。

## 产品边界（不是什么）

- **不是导航站**：不做包含几十个上百个书签的超级综合导航站。
- **不是 Web OS**：不碰文件系统、存储管理、命令行等真正的操作系统功能。
- **不过度中心化**：不做用户登录/邮箱登录/依赖开发者服务器的方案。
- **不做站内窗口嵌套**：点击图标直接在新标签页打开目标网站，不在本站内做浏览器窗口管理。
- **桌面端 only**：暂不考虑移动端适配。

## 功能假设

### 1. 书签管理
- 支持导入浏览器导出的书签 HTML 文件。
- 网页端可直接对书签进行增删查改。
- 数据持久化与跨设备同步方案设想：通过 GitHub API / Personal Access Token 将书签数据写回仓库（如 JSON 文件），解决 localStorage 无法跨设备同步的问题。

### 2. 桌面交互
- 视觉风格：苹果 macOS 桌面风格。圆角磨砂质感、Dock 栏动效、图标网格。
  - 参考案例：https://github.com/viviannnl/personal-web
- **窗口组件（仅限设置等本地功能）**：
  - 类似 macOS 的小型浮动卡片（约占屏幕 1/6）。
  - 左上角苹果风格三按钮（关闭/最小化/全屏，绿黄红）。
  - 支持拖拽标题栏移动窗口位置。
  - 设置项包含：亮暗模式切换、主题色选择。
- **书签图标**：点击直接在新标签页打开目标网站，不做站内窗口嵌套。
- 图标拖拽：桌面图标可自由拖拽摆放。

### 3. 本地轻量应用（可选，非核心）
- 设想极小辅助工具，如桌面便签（参考 menav），用于替代桌面临时 TXT 文件。
- 是否内置 To-Do、Timer 等待定，甚至可以不做。
- 数据存储：localStorage（不需要跨设备同步）。

## 技术假设（未验证）

| 维度 | 假设 |
|---|---|
| 目标用户 | 开发者/技术爱好者（能接受 fork repo + 配置 Token 的门槛） |
| 技术栈 | 以能实现类桌面交互为标准，优先选择轻量方案。Next.js 或 Vite + React 均可，具体由技术调研决定 |
| 部署 | 轻量无服务器：GitHub Pages / Vercel / Cloudflare Workers |
| 域名 | 不使用 `username.github.io`（保留给个人博客），使用项目级域名 |
| 同步机制 | v1 阶段考虑。前端直接调用 GitHub API，用户配置 Personal Access Token 存于浏览器，书签数据以 JSON 文件形式写回 public repository。MVP 可仅本地使用 |

## 待验证问题

1. **技术栈选型**：Next.js vs Vite/React vs 其他轻量方案，哪个更适合纯客户端桌面交互？
2. **书签导入的复杂度**：浏览器书签 HTML 解析是否可行？用户体验如何？
3. **GitHub API 同步的可行性**：前端直接调用 GitHub REST API 读写文件，是否有 CORS 限制？速率限制是否影响体验？
4. **拖拽交互实现**：桌面图标拖拽、窗口拖拽，在 Web 环境下的最佳实现方案是什么？
